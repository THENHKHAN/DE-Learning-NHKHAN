Core RDD properties
🔒
Immutable
Once created, an RDD never changes. Every transformation produces a brand-new RDD. This makes parallel reads safe — no lock contention.
🌐
Distributed
Data is split into partitions spread across many nodes. All nodes process their slice simultaneously — true parallelism at scale.
♻️
Resilient
Spark tracks a DAG lineage (the "recipe"). If a node fails, it replays just the failed partition's steps — on any available node.

🔧 Transformations — lazy

# Load 100M rows from HDFS logs = sc.textFile("hdfs://logs/transactions.txt") # Build the transformation chain (nothing runs yet) result = (logs .filter(lambda r: r['status'] == 'FAILED') .map(lambda r: (r['user_id'], r['amount'])) .reduceByKey(lambda a, b: a + b)) # Action — triggers actual execution across all nodes result.saveAsTextFile("hdfs://output/failed_totals")

Python list vs RDD resilience
🐍 Python list
Lives in a single process's RAM. If the process or machine crashes → all data is gone. No recovery path.
⚡ RDD
Spread across nodes + lineage tracked. One node dies → Spark re-runs just that partition's recipe elsewhere. Job continues.
🛒 Scenario: Black Friday fraud detection at scale
An e-commerce platform processes 500 million transaction logs from Black Friday. Goal: flag every user who had more than 3 failed payments (likely card-testing fraud) — in near real-time, before the shopping window closes.
Why single machine fails here
500M rows — single machine vs 20-node cluster
Walk through the pipeline
Full PySpark implementation
# Load 500M transaction logs from HDFS (auto-partitioned across 20 nodes) logs = sc.textFile("hdfs://blackfriday/transactions.json", minPartitions=20) # Step 1: Parse JSON strings into dicts parsed = logs.map(lambda line: json.loads(line)) # Step 2: Keep only FAILED transactions failed = parsed.filter(lambda r: r['status'] == 'FAILED') # Step 3: Extract (user_id, 1) for counting keyed = failed.map(lambda r: (r['user_id'], 1)) # Step 4: Count failures per user (shuffle across nodes) counts = keyed.reduceByKey(lambda a, b: a + b) # Step 5: Flag users with more than 3 failures (fraud signal) suspects = counts.filter(lambda x: x[1] > 3) # ACTION — triggers the whole plan on 20 nodes simultaneously suspects.saveAsTextFile("hdfs://output/fraud_suspects") # Result: 12,445 users flagged in ~4 minutes
